# 桌宠插件可行性分析与设计

> 调研日期：2026-11-05　范围：`deepseek-ai/deepseek-harness`、`QCYTSN/dsh-dafeiyu`、
> `huaizhuanghub/dsh-persona-dafeiyu` 三个仓库的 README 与公开说明。
> 本轮**只做分析与设计，不写插件代码**（按已确认的交付范围）。

## 1. 结论先行

**可以开发，但不建议直接 fork / 改装 `dsh-dafeiyu`。**
推荐做**独立的 TokenBoard 桌宠**：不绑定 DeepSeek Harness，以 TokenBoard 的
`--format json` 为唯一数据源，用 Tauri 2 实现三端透明置顶窗口。

三句话理由：

1. 桌宠本身已经有成熟实现，重复造轮子没价值；它的价值在**状态数据与事件源**，不在窗口代码。
2. `dsh-dafeiyu` 的状态来自 **DSH 会话事件**，而我们要展示的是**多平台 Token 消耗**，
   两者数据模型不同；绑定 DSH 等于给自己加了一个不必要的上游依赖。
3. DSH 官方明确写着 **Developer preview、会有破坏性变更**，且该桌宠的
   **代码授权与角色素材授权是分离的**，直接改会同时踩兼容性与版权两个坑。

## 2. 三个仓库的定性（调研证据）

| 仓库 | 它到底是什么 | 对本项目的意义 |
|---|---|---|
| `deepseek-ai/deepseek-harness` | DeepSeek 官方 Agent Harness，MIT，TypeScript + pnpm + Cordis，"Everything is a Plugin"；`npx @deepseek-ai/dsh web` 起 WebUI `127.0.0.1:3080`，另有官方桌面端；插件通过 `dsh plugin --profile <profile> add <pkg>` 安装 | 提供了完整的插件/插槽生态，但**处于 developer preview，官方明说会有破坏性变更** |
| `QCYTSN/dsh-dafeiyu` | 真正可用的桌宠：透明、无边框、始终置顶的原生窗口，展示 DSH 会话事件驱动的 Agent 状态（思考/查找/修改/执行/验证/等待确认/完成/错误）、项目与待办进度、DeepSeek 余额；支持拖动、摸头、戳身体、碰尾巴、气泡与声音。v0.1.23，npm 包 | **参考实现**。它的跨平台 Helper 方案、状态机、设置项、冷启动诊断都值得抄设计 |
| `huaizhuanghub/dsh-persona-dafeiyu` | **不是桌宠**，是提示词人设库插件（大肥鱼/阿茶/听澜），全局/工作区/会话三档、免重启切换，纯 JS 无运行时依赖、MIT | 参考价值在**工程规范**：回环接口三道安全闸门、`--dsw-alias-*` 语义 token 不写死色值、兼容性自检 |

`dsh-dafeiyu` 的原生窗口方案（抄设计用）：

| 平台 | Helper | 备注 |
|---|---|---|
| Windows 10/11 x64 | 随包原生 Helper | WSL2 可经 Windows 互操作启动 |
| Linux x64 | Qt Helper | 需图形桌面，glibc ≥ 2.35 |
| Linux arm64 | Python + PySide6 ≥6.7,<7 回退 | 包里无对应架构 Helper |
| macOS 12+ | Swift / AppKit，Universal | **实验性**，官方说仍需真机验证多屏 |

其它关键事实：素材为 24fps 透明 WebP、16 组动作 3444 帧、画布 412×344，
来自 `PC2005-cloud/dsh-pet`；首次启动要解压约 100MB Qt 运行库，冷启动上限放宽到 180 秒；
状态来自 DSH 会话事件，**不读屏幕**；不发起模型调用。

## 3. 三条技术路线对比

| 维度 | A. 改装 `dsh-dafeiyu` 做 DSH 插件 | B. 独立 Tauri 2 桌宠（推荐） | C. 纯 Web Widget / 菜单栏小工具 |
|---|---|---|---|
| 开发成本 | 中（要读懂 DSH 插件 + 三端 Helper） | 中高（5–8 人日 MVP） | **低（1–2 人日）** |
| 透明置顶 / 点击穿透 | 现成，三端已实现 | Tauri 2 原生支持，需逐端调 | 无原生窗口，只能浏览器内 |
| 数据源耦合 | **强绑 DSH 会话事件** | 完全解耦，读 TokenBoard JSON | 完全解耦 |
| 多平台 Token 数据 | 要自己把数据注回 DSH 事件流，别扭 | 天然支持 | 天然支持 |
| DSH 破坏性变更风险 | **高** | 无 | 无 |
| 素材授权风险 | **高**（代码/素材分离） | 可控（自绘即可） | 可控 |
| 分发 | 依赖用户先装 DSH | 独立安装包 | 无需安装 |
| 维护 | 跟上游版本走 | 自己掌控 | 自己掌控 |

**推荐：B 为主，但 P0 先用 C 验证「用户到底会不会看」**。
桌宠最大的风险从来不是技术，是做出来没人看。先花 1–2 天做一个可嵌入的
Web Widget 验证交互与刷新频率，再决定是否投入原生窗口。

## 4. 推荐架构（路线 B）

```
TokenBoard core (Python，本仓库已有)
   │  python -m tokenboard scan --format json
   ▼
PetState 快照（KPI / 速率 / 模型 / 平台 / 预算 / 异常）
   │  Tauri sidecar 每 30s 调用一次（或读固定 JSON 文件）
   ▼
Rust 侧状态机 ──► WebView 渲染角色 + 气泡 + 迷你 KPI
   │
   └─ 设置：置顶 / 点击穿透 / 大小 / 减少动态 / 刷新间隔 / 主题（深绿·浅绿）
```

**为什么用 sidecar 而不是在 Rust 里重写解析**：核心包已经把 6 个平台的
字段探测、缓存计价、品牌色都做完了，重写等于制造第二套口径。
Tauri 的 sidecar 机制正好能吃 Python 产物的 stdout JSON。

### 状态映射（把 Token 数据变成角色行为）

| TokenBoard 信号 | 桌宠状态 | 视觉 |
|---|---|---|
| >10 分钟无新请求 | 待机 | 缓慢浮动、闭眼 |
| 正常消耗速率 | 工作中 | 悠闲游动 |
| 速率 > 近 7 日 P90 | 高负载 | 加速摆尾、气泡「今天有点猛」 |
| 缓存命中率环比下降 > 10pt | 疑惑 | 歪头 + 提示气泡 |
| 单日成本超预算阈值 | 预警 | warning 色气泡（`#D4A574`） |
| 出现错误 / 扫描失败 | 异常 | danger 色（`#D08068`） |
| 当前主力模型切换 | 换装 | **徽标用该厂商品牌色**，UI 仍绿色系 |

最后一条把本项目「绿色系 UI + 模型品牌色」的规范自然延伸到桌宠：
角色框架永远是绿的，只有模型徽标随品牌色变。

## 5. 素材与授权（最大的非技术风险）

- `dsh-dafeiyu` 的代码与角色素材**适用不同授权**，仓库有 `ASSET_LICENSE.md`
  与 `assets/dsh-pet-LICENSE.txt`；素材原始来源是 `PC2005-cloud/dsh-pet`。
- 因此**不能直接拿它的 3444 帧 WebP 来用**，哪怕代码是 MIT。
- 可行做法（按推荐顺序）：
  1. 自绘 SVG/CSS 角色（风格化鲸鱼/水泡），彻底规避授权，也最轻；
  2. 使用明确 CC0 / CC-BY 的素材并保留署名文件；
  3. 联系原作者取得单独授权后再用原有帧序列。
- 「大肥鱼 / dsh / DeepSeek」等名称与标识注意不要造成官方背书误解，
  项目名建议独立（如 `TokenBoard Pet`）。

## 6. 原生窗口技术要点

| 平台 | 关键点 |
|---|---|
| macOS | `NSWindow` 透明 + `.floating` level；点击穿透用 `ignoresMouseEvents`；多显示器遍历 `NSScreen`；不要为了置顶去申请辅助功能权限 |
| Windows | `WS_EX_LAYERED` + `WS_EX_TRANSPARENT`，`SetWindowPos(HWND_TOPMOST)`；注意杀软对自解压 Helper 的实时扫描会拖慢冷启动 |
| Linux | X11 下置顶/穿透可控；**Wayland 各合成器行为不一致**，需要 fallback 到普通窗口并明确告知 |
| 通用 | Tauri 2 的 `alwaysOnTop` / `transparent` / `skipTaskbar` / `setIgnoreCursorEvents`；提供「减少动态」开关；刷新与动画都要可关闭 |

隐私边界沿用主项目：**只读本机日志、只显示聚合数值、不发任何网络请求、不显示会话标题或提示词正文**。
桌宠是常驻进程，这一点比一次性看板更需要写进 README。

## 7. MVP 范围与验收标准

**做**：透明置顶窗、点击穿透开关、30s 刷新、6 种状态气泡、深绿/浅绿主题、
模型品牌色徽标、设置面板（大小/刷新/减少动态）、数据源状态展示。

**不做**：动画帧序列、声音、余额查询、DSH 事件接入、账号体系、联网。

验收（可量化）：

| 项 | 标准 |
|---|---|
| 三端启动 | macOS 12+ / Windows 10+ / Ubuntu 24.04 均能起窗口 |
| 数据一致 | 气泡里的合计 Token 与 `tokenboard --format table` 差异为 0 |
| 资源占用 | idle CPU < 2%，内存 < 120 MB（不含自绘 SVG 时更低） |
| 隐私 | 抓包确认 0 个出站请求；设置里可见「仅本机数据」说明 |
| 降级 | 日志目录不存在时显示明确空态，而不是空白窗口或崩溃 |
| 授权 | 仓库含 `ASSET_LICENSE.md`，所有素材来源可追溯 |

## 10. 本轮为什么没写代码

已确认的交付范围是「两版本 + 桌宠分析」，因此本文件只输出设计、成本与风险，
不产出插件骨架。要启动 P0，需要你先拍两件事：

1. 走 **B（独立 Tauri 桌宠）** 还是先用 **C（Web Widget）** 验证需求？
2. 角色素材用**自绘 SVG**（无授权风险、风格更统一）还是另有指定素材？
